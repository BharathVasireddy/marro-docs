---
title: "Case workflows"
description: "Bring participants, required work and document progress into an opportunity or case."
---

A workflow is a checklist on an existing opportunity or case. It uses that record’s stage and owner, your existing contacts, task boards and document requests. It does not run a separate automation or move stages automatically.

## Set up a case

Open an opportunity and find **Workflow**. Add participants by selecting existing contacts and describing their role, such as client, applicant, adviser or service provider. A participant role does not give anyone access to the case or to private files.

Choose **Add requirement**, enter what is needed, and choose **Task** or **Document**. Search for an existing task or document request to link it. You can leave a requirement unlinked while planning; it stays outstanding until linked work is complete. Mark nonessential work optional to exclude it from the required progress count.

Before linking work, set a responsible staff member and planning deadline if needed. Assignment changes require assignment permission. Once linked, task owners and deadlines come from the task. Document deadlines come from the document request; the requirement can still name the staff member responsible for checking it. Select the linked record name to work on the source. Each row’s menu also offers **Edit requirement** and **Open task** or **Open document**.

Document requests can be linked only from the case’s explicitly connected original lead, with access to that lead. A contact’s previous lead is not used automatically. Cases without a source lead can plan document requirements but cannot link portal requests. Create and review requests through the existing lead workflow.

## Read progress

- Tasks count as complete only when their task-board stage is marked complete.
- Uploaded documents still await review. Only accepted requests count as complete.
- Changes requested, overdue work, missing owners and unlinked requirements remain visible.
- An archived, withdrawn or inaccessible source never counts as complete. The workflow does not reveal its private content.

The progress count covers required items. Completing the checklist does not automatically advance the case, approve a loan, establish compliance, send a message or collect payment.

## Reuse a checklist

On a case with no requirements, open **Workflow actions**, choose **Reuse checklist**, and select another case you can access. Review its requirements and apply them once. Only requirement definitions are copied: participants, task/document links, staff assignments and dates are cleared. Later edits to the original do not change the copy.

If either case changes while you review it, refresh and review the latest version. This prevents duplicate application and lost edits.

## Ask Marro and mobile

Ask Marro to read a case’s workflow, explain blockers, add a participant, update a requirement or reuse a checklist. It asks for confirmation before applying workflow changes. Task updates and document acceptance use their existing permissions and review rules.

The mobile case screen shows participants, work and blockers. **Ask Marro about this workflow** opens the shared assistant to propose changes for confirmation. Staff WhatsApp uses the same actions and permissions. Workflow editing forms are on the web; mobile edits are through Ask Marro.

For example, a mortgage broker could track applicants, an adviser, evidence review and a submission task. Another team could use the same fields for onboarding or service delivery. Marro tracks the work; staff make professional and eligibility decisions.
